# 经验与依据

2026-10-21将原手动包交接改为Git协作。下面保留原经验中会改变接手决策的部分，不复制历史附件与完整报告。

| 本项目经验 | 交接时的具体动作 |
|---|---|
| ①②共同实施却容易只写① | 分别保留贡献；②输入语义与①存储正确是两项验收 |
| 条数、种子覆盖和48项测试曾被当作语义正确 | 写明检查范围，F1/F2人工语义闭环与离线回归分开 |
| 默认浏览器没有对应实抓证据 | 补最小验证或收敛支持范围，不凭缺证据认定故障 |
| 删除文档后因chunk引用保留旧记录 | ③⑤同时处理active、版本和索引同步，不能只看向量结果 |
| ③有检索源码但④仍缺运行条件 | ③补同版数据、模型和构建加载说明；④直接测可复现Retriever，⑤并行做N5应用适配，底层首测不等额外封装 |
| 多份交接报告、diff和清单持续漂移 | 一张节点状态表＋Git提交/PR说明；历史放Git，原始日志留本机 |
| Git代码版本并不包含完整数据 | 组内快照交付另记文件、SHA、接收者及目标位置 |

原技能已引用的公开工程实践，作为思路来源，本次未重新核对其网页版本：

- Google SRE的接管准备度：按实际接收标准和操作验证交接，课程原型不机械套生产流程。来源：`https://sre.google/sre-book/evolving-sre-engagement-model/`。
- GitLab的完成标准：要求关联验证证据；待办要说明责任与延期影响。来源：`https://docs.gitlab.com/development/definition_of_done/`。
- Atlassian的岗位职责：重叠任务写主责与协同，建议承接不能冒充已确认。来源：`https://www.atlassian.com/team-playbook/plays/roles-and-responsibilities`。
- Microsoft的决策记录：保留关键接口选择的原因、影响及版本关系，不为每个小改动建独立文档。来源：`https://learn.microsoft.com/en-us/azure/well-architected/architect-role/architecture-decision-record`。

迁移使用时读取新项目真实接收契约；支持增量的接口不应被本案例的完整快照要求替代。这里只提供判断方法，不替团队确认接收、课程截止或外部发送权限。
