# 岗位节点与Git交接

在本仓库先读[协作与需求节点](../../../docs/协作与需求节点.md)，只加载当前节点和[对应岗位提示词](../../../docs/岗位提示词.md)。接口或输入需要查证时再读[开发指导](../../../docs/Harness开发指导.md)。迁移到其他项目时，改用该项目真实的角色、节点和状态入口，不强套①—⑥。

## 核对输入与责任

- 识别当前实施者、接收者、节点、Git提交/分支及工作区变更；数据另外核对文件与SHA，索引另外核对模型和构建版本。提交时间和文件mtime不能证明完成。
- 把节点要求与实际实现、diff和验证对应。区分已验证、部分完成、待验证与未实施；结构/离线测试不能替代语义、真实运行或接收者确认。
- 当前返工是既定要求缺陷或必要证据不足；下游任务是原定新增职责，分别指定主责、协同、完成标准与解除阻塞条件。共同实施时保留所有岗位贡献，不能省略②。
- 本项目②F1/F2须闭环，F3补验证或收敛声明；不能交给③⑤掩盖。③正式构建等N2，⑤先交N5查询通路再做完整Agent；英文路线不等中文能力。

## 在Git里完成交接

1. 根据用户请求完成准备、复核或接收所需部分；可独立推进的代码、mock、脚本先做，正式验收需要上游真实输入。仅请求文档时不扩大为导入数据或重建索引。
2. 按实际变更做最小必要验证，写日期、命令、退出码/结果、对应版本和未覆盖项。引用旧结果注明历史未重跑；不要编造数据SHA或模型实验。
3. 更新现有节点表对应行，写候选/阻塞、证据和接收者。实施者可以提交候选，正式通过须接收者确认；没有确认就保持待验。
4. 准备commit/PR说明：节点与全部实施者、本次变化、输入数据SHA及模型/索引/题集版本、实际验证、遗留/接收人/下游影响。代码由Git交接，详细日志留`runs/`等忽略目录。
5. 实际数据按组内渠道交付，同时说明文件名、SHA及相对目标路径；未拿到数据的下游仍然阻塞。建议位置与已存在位置分开，完整快照契约下不把修补行当全量。

默认复用当前一张状态表，不新增交接报告、diff副本、附件包或哈希清单；代码版本交给Git。用户明确需要可离线分享的包或审计留档时，按该请求生成必要产物。删除重复文档前迁移有效结论、检查调用和链接，并保留Git历史中的追溯位置。

涉及制度规则与目标流程时先读[知识研究入口](../../../knowledge/README.md)：原文、身份/届别、条件/例外、来源版本及规则ID共同核对；官网索引或HTTP 200不自动代表完整政策已核实。候选规则不能直接进入正式索引，规则表与golden题集分开。

涉及检索、LLM、RAG或Agentic RAG评测时读取[评测启动入口](../../../evals/README.md)。区分知识库、golden与rubric；④交证据及检索统计，⑥交事实/行为与评分，⑤交被测系统。使用真实快照做DEV校准与独立CORE，题集绑定SHA并交叉复核；模型只收输入白名单，真实gold与原始trace留忽略目录。结构通过不能登记为性能达标。

跨角色冲突优先查既有契约；上游错误不能转嫁为下游“顺便修”。变更数据、query编码、过滤、索引或题集后指出受影响节点，让④⑥复验受影响结果，不沿用旧版本数字封版。

完成前检查：岗位与节点无遗漏；现有入口和相对链接有效；状态与证据一致；数据传递方式明确；暂存区不含个人信息、密钥、全文数据或运行产物。外部提交/推送按用户已授权范围执行，不因调用skill而自动向组员发送消息。

最后简短说明已完成、当前阻塞、接收者下一步和更新的唯一入口。经验与已有工程依据按需见[经验与依据](references/经验与依据.md)。
