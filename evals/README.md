# 测试与快速证据标注：从这里启动

更新：2026-10-26。适用英文路线。先读本页，再运行5道DEV练习；无需模型、API或真实语料即可检查文件契约。**合成练习不是CityU政策、正式golden测试集或模型性能结果。**

## 三种材料放哪里

| 材料 | 是什么、由谁维护 | 位置 | 能否进入模型 |
|---|---|---|---|
| 知识库 | 学校公开正文及来源；②采集、①接收、③构建索引 | 真实文件在本机`data/corpus.jsonl`、数据库和索引；公开练习是`synthetic_corpus.jsonl` | RAG/Agent通过检索取得的正文可以进入上下文；不能混入题目、标准答案或评分指令 |
| golden测试集 | 问题、适用条件、必要事实、正确证据、预期行为和禁止结论；④⑥共建 | `dev_cases.jsonl`是公开合成DEV；真实冻结TEST及标注放忽略的`evals/private/` | 只向系统发送题目与用户本来知道的条件。gold、预期动作、风险标签和判分依据留在评测侧 |
| rubric | 通用的判分规则、分档和阻断项；⑥主责、④复核 | `rubric.json` | 用于人工/评测器，不直接作为用户问题或检索正文发给被测模型 |

golden指经人工核实并冻结的参考标准，不意味着有文件就已冻结。`draft`是草稿；本包`synthetic_ready`只表示可用于练习。真实`frozen`须绑定语料SHA、题集版本、④⑥审核和接收记录。这里的JSON校验不能代替人工语义审核。

## 四类测试分别测什么

| 模式 | ⑤提供什么／③已有接口 | ④运行与统计 | ⑥检查 |
|---|---|---|---|
| retrieval | 直接调用③的`Retriever.search(query, topic=None, k=5)`，返回Hit | 首轮Hit@5、必要事实证据覆盖、完整证据覆盖、耗时 | 抽查相关证据是否真的支持事实；不评不存在的生成答案 |
| llm | 同一生成模型直接回答，不给知识库、检索和联网工具 | 事实覆盖、任务结果、耗时、usage | 正确性、澄清和越界行为；无检索上下文时忠实度N/A，来源保障指标单列 |
| rag | 固定一次本地Top-5，将证据交同一LLM回答并引用 | 与llm/agentic_rag成对比较 | 事实正确、条件完整、引用支持和误拒答 |
| agentic_rag | 同一知识库和模型，允许动态选择/改写/补检索，有停止及预算限制 | 任务收益、检索次数、总token、耗时和成功任务成本 | 是否补齐缺口、正确停止、回答和异常行为 |

当前`--ask`是Web搜索Agent，不能冒充上述本地RAG模式。四模式尚未由本包实现；本包提供启动材料、输入契约和校验工具，不伪造可运行的`--mode rag`命令。④负责实验比较，⑤负责系统模式与修复，⑥负责回答评分。

普通RAG需要“检索→LLM生成”；③的检索模块本身不是完整RAG。Agentic RAG不强制联网，Rerank本身也不等于Agent。联网模式若保留，单列Web，不把外部知识收益归为编排收益。

## 先用5题练一次：10分钟定位，人工审核不计固定工时

在仓库根目录执行（只需Python标准库）：

```powershell
python -m scripts.check_eval_assets
python -m scripts.check_eval_assets --export-inputs runs/startup/dev_inputs.jsonl
```

第一条核对3份合成正文、5题、证据摘录、事实ID、SHA和rubric权重；第二条只导出`case_id`及`input.query/persona/as_of`，不含gold。导出只允许写入本仓库`runs/`，拒绝覆盖已有文件。记录ID是评测元数据，不必加入LLM提示词。

SHA按文件原始字节计算，仓库`.gitattributes`统一LF换行。真实组内快照也须按交付字节保存；重新格式化或改换行后要重新计算SHA并复核绑定。导出工具使用字段白名单，但`persona`仍须人工保证只含用户已知条件，不塞入隐藏答案。本启动字段只覆盖`answerable/clarify/unanswerable`三类；部分可回答、冲突及多轮场景先留草稿，扩展契约和校验后再冻结。

练习包含3道有证据的问答、1道缺条件需澄清、1道无法查询个人状态的问题。正向检索分母只有前3题；不能把澄清和个人状态题作为检索失败。合成答案公开，不能用于独立盲测或宣称真实命中率。

④⑥分别打开同一题：④标“应该检到什么”，⑥标“应该答什么”。先各自判同一份答案，再核对分歧。不要先让模型自己产金标，再让它给自己判分。

## 用真实语料快速标注

1. **①给输入身份**：从组内取得验收快照与SHA。③交对应模型/索引和可复现命令。缺数据不妨碍写草稿和脚本，但不能冻结金标或填写正式成绩。
2. **④先选证据再出题**：从语料内已有答案的段落选题；先覆盖八主题，先做5道DEV校准，再独立制作20道CORE。官网有、语料没有是覆盖缺口，不能强列为语料内可回答。
3. **④标证据**：保存官方URL、语料内小标题/段落、最短充分摘录和支持的事实ID。URL相同不等于chunk相关；chunk变化时从原文定位重新映射。原网页更新不应静默替换冻结证据。
4. **⑥补事实与行为**：写必要事实、适用身份/学年、预期回答/澄清/部分回答/转介、禁止结论；无答案题不要编造事实。金额必须连币种和收费口径，日期必须连事项与学年。
5. **交叉复核**：④⑥独立读原文，不能只看对方答案。分歧找①或相应内容负责者裁决；记录裁决和版本。置信不足保留draft。
6. **先试评再冻结**：5题DEV用于调试和评分校准；正式20题使用不同事实/意图，并按同源事实与改写分组隔离。针对TEST修复后，该套成绩属于回归，泛化另用未见题。

最小题目记录见`dev_cases.jsonl`。制作真实草稿时复制字段而非合成答案：改`id/split/query/persona/as_of`，填真实`corpus_sha256`，标`synthetic=false, review_status=draft`，再填`required_facts/gold_evidence/sufficient_evidence_sets/forbidden_claims`。每条证据的`quote`必须是该快照正文的连续摘录；表格跨段需多条证据，不拼出原文不存在的一句。

真实文件的结构门示例（文件须自行制作，当前不存在）：

```powershell
python -m scripts.check_eval_assets --corpus data/corpus.jsonl --cases evals/private/core.jsonl --require-frozen --min-answerable 20
```

`--require-frozen`检查真实TEST、审核标记及版本字段；这些是人工记录的结构条件，程序不能证明审核已实际发生。不要为了过校验把未审核记录改成true。真实金标不自动公开，盲测结束后也须先检查隐私和摘录范围再决定发布。

真实CORE20的20道须为语料内可回答、用于正向检索的独立题；澄清、个人状态及故障题另加，不挤占这20道。版本变更后重新核对受影响证据。题集与rubric的版本也须随正式结果保存。

## ④⑥的同一题如何分工

| 共享字段 | 主责 | 检查方式 |
|---|---|---|
| id、题干、split、persona、as_of、语料SHA | ④起草，⑥复核 | 模型能看到影响答案的用户条件；评分侧标签不塞进提示词 |
| gold_evidence及事实→证据关系 | ④ | chunk须支持至少一个必要事实；最小充分证据集合覆盖全部必要事实，可允许等价组合 |
| required_facts、expected_action、forbidden_claims | ⑥主责，④核对证据 | 每项事实适用且有依据；澄清题按必要澄清计分，不要求杜撰答案 |
| 检索runner、逐题统计和三系统比较 | ④ | 保留失败题；不只统计成功返回；不按URL粗匹配冒充事实证据覆盖 |
| rubric、回答/引用标注和分歧裁决 | ⑥ | 与检索评分分开；正确但不在参考答案中的额外事实也要核实，不能直接判错 |

⑥可另起少量Agent澄清、缺证据、冲突、工具失败、提示注入场景，但沿用共享ID/来源和字段，不重做另一套相同20题。注入载荷放模拟工具正文；“这是攻击”及预期动作只留评测侧。

## ⑤输出契约与公平比较

⑤的runner只读上面导出的inputs。下面是**待实现的结果字段约定**，不是已取得的运行记录：

```json
{
  "case_id": "DEV-001",
  "mode": "rag",
  "status": "ok|error|unsupported",
  "answer": "actual output",
  "retrieval_rounds": [{"query": "actual query", "hits": []}],
  "final_context_chunk_ids": [],
  "citations": [],
  "tool_calls": [],
  "timings_ms": {"total": null, "query_encoding": null, "search": null},
  "usage": null,
  "versions": {"git_sha": "actual", "corpus_sha256": "actual", "index_id": "actual", "model": "actual", "prompt_sha256": "actual"}
}
```

Hit沿用`src/retriever.py`的字段。分别记录首轮Top-5、各轮累计证据、最终上下文和答案引用；不能把Agent多轮所有Hit合并后叫Hit@5。来源URL列表不等于实际引用。usage不可用写null，不估造费用；异常不能落密钥、原始HTTP响应或个人数据。

④比较llm/rag/agentic_rag时固定问题、生成模型、语言、解码参数及本地语料；报告总调用/token预算和真实成本。工具故障按适用模式单独报，不强测纯LLM的索引损坏。普通题、澄清、无答案与故障分层统计。金额/期限/身份等关键错误逐条列出，不让平均分覆盖。

对“内容正确”三系统共同评分；忠实度和引用依其可用证据分别报告，纯LLM没有检索上下文时记N/A。若报告统一的“有证据产品任务成功率”，须声明它包含证据要求，差距不能全部解释为事实回答能力。小样本只报告n/N和限制，3次重复不等于3倍独立题。

## 文件与隐私边界

- 本目录公开文件仅含人工编写的合成内容，URL为不可用示例域名`example.invalid`，不含CityU全文、真实金额/日期、学生身份或组员聊天。
- 真实语料、数据库、索引、原始答案/trace、私有gold分别留`data/`、`runs/`、`evals/private/`等忽略路径；禁止把本目录整体加入索引。即使是合成的gold/rubric，也应通过角色隔离练习。
- 组员人名和群聊留本地协作文档；公开启动材料只用①—⑥。结果公开前检查个人信息、账号、密码、API密钥及引用长度。
- 当前仅启动包已可离线校验，真实20题、四种模式和性能结果均待相应岗位实施，不更新N4/N6/N7为通过。
