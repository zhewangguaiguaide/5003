柯燕萍｜Agent评估｜11月16日建议稿。采用本次N5独立评测的脱敏结果，供①接入、④核对统计、⑤确认F1状态字段。

## 前端现状

截至本次检查，GitHub 可见分支中未找到可启动的 Streamlit 页面。N5 已提供 `--ask-local ... --json`，返回一次本地 RAG 的答案、引用、检索记录和状态。前端本地版本或未推送分支由①确认。

| 规划入口 | 内容 |
|---|---|
| F1 问答工作台 | 输入、答案、实际引用与调用状态 |
| F2 数据与数据库 | 数据覆盖、数据库结构、只读 SQL 和执行计划 |
| F3 检索观察 | 查询、筛选与 Top-5 片段来源 |
| F4 评估结果 | 题集、配置、指标与失败归因 |
| F5 项目资料 | 报告、仓库、贡献与复现入口 |

## 前端建议问卷

| 问卷项 | 建议 |
|---|---|
| Q1 展示目标 | 观众能区分证据命中、系统返回状态和任务通过，并能看懂引用为何可能不支持某个断言。 |
| Q2 必需项 | F4先显示 YP-CORE 20题、N5一次本地RAG、E5-only、AI初评待人工复核。其下展示严格证据命中15/20、17回答／3拒答、初评14通过／5失败／1待裁决。F1展开实际引用片段并显示本次调用状态。关联M5-A/B、M4-C/D。 |
| Q3 建议项 | M5-C同屏展示退款案例。系统召回了两类学生的资料，回答却把适用对象与办理渠道对应反了。展示脱敏归因，标记关键失败候选、待人工核验。建议占原M5-C的10秒。 |
| Q4 可交付素材 | F4在演示时读取固定的脱敏结果快照。素材见本目录 results/yp_run_summary.json、yp_core_run_status.png、yp_core_ai_provisional.png 及 results/README.md。评测交付提交 bd3530ef19f1a7460becc880fea7ac034901ecd7，被测后端提交 2373dd1d3863438404d75b49c6bcc27a2f2e8cbb。 |
| Q5 状态与验收 | F4显示来源版本与分母，未人工复核显示对应状态，缺数据显示待评。F1按实际后端结果分别显示回答、证据不足、检索失败或生成错误。澄清有实际输出时显示需要补充的条件。若后端尚无独立澄清状态，保留实际状态并呈现澄清文本。 |
| Q6 画面短字幕 | “Retrieval evidence, response status and provisional task judgments measure different things.” |
| Q7 接入与依赖 | ⑥交脱敏数据、图和归因。④确认统计口径，⑤确认F1可用字段，①确认页面接入和冻结版本。录制安排沿用组内认领。 |

F4布局建议为“题集与版本 → 三组结果 → 一条失败归因”。将5类非检索场景放在可展开区，注明真实调用或隔离测试。韩上的原CORE20若同页展示，单独列题集与配置。15/20和17/20来自不同题集，不能绘成rerank前后对比。页面数据只取脱敏交付文件，私有金标和逐题记录留在评测目录。
