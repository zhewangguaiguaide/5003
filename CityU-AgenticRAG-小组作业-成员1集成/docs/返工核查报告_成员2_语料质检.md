## 已核实并修复的问题

| 返工项 | 核查与改动 | 验证结果 |
|---|---|---|
| R1 失败 URL 持久化 | 网络/HTTP 错误保存至 records.error，已有成功原文不会被失败覆盖；错误记录不视为成功已抓 URL。全量模式逐栏目保存 URL、尝试次数、错误及汇总到 crawl_audit.jsonl；接入已有 crawl_runs | 种子复核写入 8 条 crawl_runs；原始层保留 31 条失败记录，导出不含失败记录 |
| R2 缺失种子补抓 | 新增 --full，先处理所有种子，再扫描新详情；命中已抓详情跳过但不停止整栏。默认增量模式仍维持 Harness 终止约定 | 13/13 种子均为 ok；八栏目有效语料共 159 条 |
| R3 student-visa 渲染退化 | 本机 HTTP 实测能拿完整正文；修正 StealthyFetcher 的类调用方式、关闭 network_idle 等待；HTTP 非成功状态和登录重定向明确判失败 | HTTP 正文 8,916 字符。没有证据证明历史退化一定由 disable_resources 导致；浏览器模式修复未单独完成 live 验证，本轮使用 HTTP |
| R4 导航薄页 | 加入短正文多行导航判定，采集与导出共享过滤规则；失败/空白正文不进入去重后的语料 | 报告点名的 ResidenceHalls（348 字符）、HallAdmission（341 字符）均已从 corpus 排除；原始层留存 |
| R5 重复标题 | 使用首个 title 元素，解码 HTML 实体，折叠完全重复的两半标题；导出和 documents 迁移同样清理旧记录标题 | ARRO 标题不再重复拼接 |

额外根因：ARRO HTML 的 `<base href>` 原先未参与相对链接解析，导致 /arro/enrl/... 被拼成 /arro/regu/enrl/... 或 /arro/impd/enrl/...。修正后注册栏目由 1 条增为 18 条。因此历史缺页不能统一归因于“瞬时失败”。

失败修复循环现在不会因第一次回放无进展而放弃第二次；修复计数按真正恢复的 URL 统计。HTTP 403/404 和登录重定向不会重复等待；导航薄页与瞬时超时仍可回放。
