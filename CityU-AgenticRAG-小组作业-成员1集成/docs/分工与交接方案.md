## 五、接口契约（v1，冻结后作为开发依据）

### 5.1 `data/corpus.jsonl`（导出语料，一行一条）

由 `python -m src.main --export data/corpus.jsonl` 产出，字段与 `src/storage.py::Record` 一致：

| 字段 | 类型 | 说明 | v2 需新增 |
|---|---|---|---|
| `url` | string | 唯一键，幂等依据 | — |
| `title` | string | 页面标题 | — |
| `source` | string | 来源站点（如 `www.cityu.edu.hk`） | — |
| `content` | string | 清洗后的正文（纯文本） | — |
| `date` | string | 内容发布日期（ISO），无则回落抓取时间 | — |
| `crawled_at` | string | 抓取时间（ISO） | — |
| `image_urls` | string[] | 图片地址 | — |
| `file_urls` | string[] | 附件（PDF/Office）地址 | — |
| `error` | string | 抓取失败原因，成功为空 | — |
| `topic` | string | 八大主题之一 | — |
| `column` | string | 栏目名（对应 `config.yaml`） | — |
| — | string | 学年标签，用于时效性标注 | **`academic_year`**（① 负责补齐） |

> 切块由 WS-B 负责，切块结果**不回写 corpus.jsonl**，而是进入 `chunks` 表（见 5.3）。

### 5.2 检索层接口（WS-B 对外唯一承诺）

```python
# src/retriever.py
@dataclass
class Hit:
    chunk_id: str
    doc_id: str          # 对应 documents.url
    text: str
    score: float
    url: str             # 溯源用
    title: str
    topic: str
    academic_year: str

class Retriever:
    def search(self, query: str, topic: str | None = None, k: int = 5) -> list[Hit]: ...
    def list_topics(self) -> list[str]: ...   # 供 router 做候选工具枚举
```

**验收**：给定 20 条已知答案的问题，`search()` 的 top-5 命中率 ≥ 70%（④ 负责度量）。
**降级约定**：检索不到时返回空列表，**不得抛异常**，由 ⑤ 决定是否走联网搜索兜底。

### 5.3 存储层 schema（① 负责落地，草案）

```sql
-- 现有 records 表保留（采集原始层），新增下列表；由迁移脚本 import_from_records()
documents(url TEXT PRIMARY KEY, title, source, topic, academic_year, date,
          crawled_at, content, image_urls, file_urls)          -- 3NF 元数据
chunks(chunk_id TEXT PRIMARY KEY, doc_id TEXT REFERENCES documents(url),
       ord INTEGER, text TEXT, embedding BLOB)                  -- 向量列/独立 ANN 索引
crawl_runs(run_id INTEGER PRIMARY KEY, started_at, finished_at, column_name,
           new_count, skip_count, error_count)                  -- 幂等/增量审计
qa_logs(log_id INTEGER PRIMARY KEY, question, answer, citations, latency_ms, created_at)
-- 索引：documents(url) 主键；(topic, academic_year)；crawled_at；chunks 向量 HNSW
```

## 六、协作与交接规范

### 6.1 交接必备五件套（缺一不可）

1. **契约**：接口签名 / 字段表写进本文件第五节或 `docs/接口定义.md`；
2. **可复现命令**：接手人照 `README.md` Quick start 能跑通；`.venv` + `requirements.txt` 锁版本；
3. **测试**：`python -m unittest discover -s tests` 必须绿；新模块自带离线 eval（照抄现有 `MockStorage` 传统）；
4. **数据**：一律用 `--export data/corpus.jsonl` 传 JSONL，**不传 `.db`**（避免二进制冲突与重复触发 WAF）；
5. **交接单**：按附录 A 填写，格式范例见 `docs/Harness开发指导.md` 第 6 节「实测特有的坑」。

### 6.2 Git 规范

- 一人一分支（`feat/ws-b-retriever`），走 PR，**合并前 main 必须能跑**；
- `data/` 产物已 gitignore，不进仓；只提交代码、schema、文档、测试；
- 提交信息：`[WS-B] add hybrid retriever + HNSW index`；
- 每周五 demo 后由 ① 打 tag（`w2-corpus-full`、`w4-retriever`…），报告里可用作版本证据。

### 6.3 交接节奏

- 每个工作流**至少交接一次**（在里程碑切换点），交接人主讲 15min + 提问 15min；
- 交接完成判据 = **接手人能独立跑通该模块的验收命令并解释其输出**；
- 上下文管理沿用 Harness 指导的诀窍：**一次只交接一个模块的一类问题，交接完清空上下文**。
