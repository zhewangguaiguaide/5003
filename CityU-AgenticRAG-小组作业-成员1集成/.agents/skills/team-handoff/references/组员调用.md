# 组员调用

技能名称：`team-handoff`；界面名称：组员交接与返工复核。适用于不同小组项目，不依赖本机Python、原项目数据库或额外连接器。

## 放到哪里

将分享ZIP解压到自己实际项目的根目录，最终结构应为：

```text
<你的项目根目录>/
  .agents/
    skills/
      team-handoff/
        SKILL.md
        agents/openai.yaml
        assets/交接报告模板.md
        assets/返工清单模板.md
        references/经验与依据.md
        references/组员调用.md
```

也可复制整个`team-handoff`文件夹到项目`.agents/skills/`中。只复制`SKILL.md`会丢失模板和参考；额外包一层ZIP名称文件夹会导致路径不符合此结构。若已有同名技能，先核对版本再替换。

本次实际创建于`CityU-AgenticRAG-小组作业-成员1集成/.agents/skills/team-handoff/`，路径从原工作区根目录算。使用该项目时在Codex打开“成员1集成”项目目录；在它的父工作区启动时，不保证发现子目录内的技能。也可以在提示中明确要求读取该路径的`SKILL.md`及所需参考执行。

Codex的本地技能位置和调用方式依据2026-10-12官方Build skills文档。CLI或IDE可用`/skills`或输入`$`选择技能；桌面端通过技能入口选择，或明确指定本地`SKILL.md`。如果没有发现新增技能，核对项目目录和文件结构，再重新启动Codex。网页ChatGPT使用本地ZIP与桌面项目目录的方式不同；本包未发布为插件。

## 给组员的调用示例

以下`<...>`请换成真实路径与岗位，可复制到Codex；补交材料不齐时也能先生成有证据的部分，但结果会注明缺口。

**②准备补交：**

```text
使用 $team-handoff。项目是<项目目录>，我是成员②。根据<返工清单>核对<修正版目录>，保留已完成成果，列出仍需返工或补验证的事项。更新给①验收、供③接手的交接文档，说明每项补交材料的文件位置、完成标准与验证证据。
```

**①复核并联合交接：**

```text
使用 $team-handoff。比较<返工前目录>、<验收报告>和<返工后目录>，并核对<集成项目目录>。明确本轮必须返工和可交给后续岗位的工作；分别体现成员①与②实施成果，更新至成员③的联合交接报告。有返工时更新给②的操作清单，详细证据放附件。
```

**③接收验证：**

```text
使用 $team-handoff。我是成员③，接收<交接包>和<项目目录>。核对实际输入、读取入口、必要环境和最短验证，说明当前可用范围、上游仍需修复的问题和③自己的任务；更新接收报告，历史测试与本轮执行结果分开记录。
```

**整理过多文档：**

```text
使用 $team-handoff。整理<交接目录>，沿用已核实结论，维护当前联合报告，有返工时保留操作清单。详细材料放附件，旧版集中归档。写明每份给谁看、附件原件位置、补交暂存位置、项目目标位置及已存在或建议新建状态，更新链接和本地分享包。
```

需要实际修改代码时，在请求中明确实施范围；“写交接”本身不包含修改源码与导入数据库。需要外部发送时另行明确发送对象和渠道。

## 默认产出与发送对象

默认一份当前联合交接报告供接收岗位阅读；有返工时增加给返工主责的操作清单。实际项目和必要数据另外按项目约定提供，日志、diff及证据放附件；技能包仅含方法与模板，不含项目交付物。

②按操作清单修正，①核验并接收，③根据联合报告开始下游工作；其他分工项目按真实岗位调整。发给组员使用的是技能ZIP，发给②返工或③接手的是项目交接包，按用途选择。
